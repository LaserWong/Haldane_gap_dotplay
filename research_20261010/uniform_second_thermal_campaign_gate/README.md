2026-10-10 23:28 UTC. This is a PRODUCER runner candidate. Independent review and root authorization are REQUIRED before any campaign. The package executed no new heat columns. Its tests were limited to kernel compilation, L4 metadata generation and validator fault injection. The thermal pilot and scalar packages remain frozen.

## Implementation

kernel.cpp extends the reviewed local pilot kernel. It corrects stale comments to match the 281-step real I/P proof and adds a read-only matrix-output mode. Heat arithmetic is unchanged. The kernel uses C++17/GMP, with no BLAS or eigensolver. Compile with python compile.py on CPU0, with limits of 512 MiB and 120 CPU seconds. Runtime children use one selected CPU, 256 MiB and <=120 CPU seconds each. Compute children also obey the remaining configured job budget, rounded to integer seconds. Parent overhead and metadata preparation are additional bounded costs. A 6-hour aggregate campaign must therefore include externally monitored process CPU.

campaign.py requires an explicit prepare/validate/run action, a physical length in 4..12, seam I/P, and an output directory OUTSIDE this frozen package. It has no implicit campaign action. The default run quota is one new batch and 120 CPU seconds. Unrestricted batch counts require root authorization. The recommended batch size is 16, with a maximum of 32. Each case must use a separate output directory. An exclusive .lock prevents concurrent writers to the same case. An orphan lock or .tmp causes a stop for manual inspection rather than silent recovery.

The metadata for each case binds beta49/4, shift700741/500000, Q2^55, cutoff280, mode(nonnegative magnetization), batch size, SOURCE+BINARY+COEFFICIENT+WRAPPER SHA256, ordered physical orbit lists and their SHA256, and the canonical sparse matrix-output SHA256 for every sector. Each invocation regenerates all physical matrix/orbit metadata and compares it exactly. The complete orbit multiplicity is 3^n. The runtime source package is immutable. Rebuilding a binary changes its pins and invalidates previous bindings unless an explicit, independently audited migration is provided.

Batch names deterministically encode M/start/count. Each stored JSON has a canonical payload SHA256. Resume validation checks identity, all pins, case digest, matrix/orbit digests, exact ordered codes and multiplicities, count, nonnegative integer norms within (Q+E_n)^2, and weighted sum. It rejects unknown batch files, duplicate or missing records, mismatched counts, stale hashes, partial writes, holes and corrupt JSON. A complete case requires every expected batch exactly once, globally unique representative codes, and multiplicity 3^n. Atomic temp write+fsync+rename exposes only complete batch results. After inspected cleanup, an interrupted current batch can safely be recomputed. Existing valid batches remain read-only and idempotent.

Only AFTER full independent aggregation does finalize read the inherited published centers/W integers. It then computes the rational trace interval, checks center+/-30e-6, and reports whether the printed totals agree. Printed totals never determine the columns. The final certificate binds every batch payload digest. A disagreement in printed W alone is diagnostic. Success is determined by the exact enclosure requirement. Even a complete case remains a producer physical certificate pending review.
